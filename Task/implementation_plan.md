# AIChatView 第一层视觉复刻实施计划

## 目标
将 `test.html` 第一层首屏视觉完整迁移到 iOS 原生 `AIChatView.swift`，优先复刻以下体验：
- 顶部标题与中间球体形成明确视觉焦点。
- 中心球体呈现液态玻璃、霓虹折射、柔和外发光的高级质感。
- 球体后方存在缓慢旋转的 mesh 线框层，增强空间感。
- 球体周围 3 个 prompt tag 以固定锚点悬浮排布。
- 底部输入框、提示文案、麦克风按钮组成稳定的首屏交互区。

本次计划只针对“第一层首屏”做高保真复刻，不把 Layer 2/3 的业务切换混入同一阶段，以避免视觉实现被交互逻辑打断。

---

## 对标范围
以 `Task/test.html` 中以下部分作为首屏对标基准：
- 标题：`.title`
- 中心容器：`.core-container`
- 背景线框：`.orb-mesh`
- 球体外层：`.orb-outer`
- 球体核心：`.orb-core`
- 流体层：`.orb-fluid-1` / `2` / `3`
- 高光层：`.glass-reflection`
- 悬浮标签：`.prompt-tag`
- 输入框：`.chat-input-wrapper`
- 麦克风按钮：`.mic-btn-outer`

不纳入本阶段的内容：
- offers 列表页
- details 详情页
- success 成功页
- 首屏之外的完整导航流转

## 实现策略

### 1. 首屏结构拆分
将 `AIChatView` 的第一层拆为 5 个独立视觉组件：
- `AIChatHeroHeaderView`
  - 负责标题、副标题、关闭按钮。
- `AIChatOrbSceneView`
  - 负责 mesh、外发光、球体、prompt tag 的整体排布。
- `AIChatOrbView`
  - 只负责球体本身的材质和动画。
- `AIChatInputBarView`
  - 负责底部输入框和发送按钮。
- `AIChatVoiceDockView`
  - 负责 `Hold to Talk` 与麦克风按钮。

### 2. 球体实现路线
球体不直接追求 1:1 翻译 CSS，而采用 SwiftUI 可稳定落地的分层方案：
- 基础层：不规则椭圆球体轮廓
  - 使用 `Canvas` 或自定义 `Shape` + `TimelineView` 驱动形变。
  - 形变幅度控制在轻微范围，避免动画失真。
- 材质层：液态玻璃主体
  - 使用 1 层主渐变 + 3 层径向流体色斑叠加。
  - 颜色以 cyan / violet / pink / blue 为主。
- 折射层：内阴影与边缘高光
  - SwiftUI 无法直接复刻 CSS `inset shadow`，改用多层 overlay + blur + blend mode 模拟。
- 外发光层：环形 glow
  - 用 1 到 2 层旋转渐变描边和外部模糊光晕实现。
- 高光层：玻璃反射
  - 用倾斜白色渐变块实现顶部高光。

### 3. Mesh 背景实现路线
`test.html` 的 `orb-mesh` 是第一层构图关键元素，必须单独实现：
- 使用 `Canvas` 绘制 4 到 6 条同心变形路径。
- 路径颜色使用低透明度 cyan / purple / pink。
- 整层以极慢速度旋转，周期建议 24 到 36 秒。
- mesh 必须位于球体后方，且不盖住 prompt tag 文案。

### 4. Prompt Tag 布局策略
首屏需要固定 3 个悬浮标签，而不是普通纵向列表：
- `tag-1` 左上
- `tag-2` 左下
- `tag-3` 右中
- 使用相对球体中心的锚点布局，不使用 `VStack/HStack` 平铺。
- 小屏下允许轻微缩放和换位，但不能挤进球体区域。

### 5. 底部交互区实现路线
底部区域按 3 层结构实现：
- 输入框
- `Hold to Talk` 文案
- 麦克风主按钮

要求：
- 输入框始终位于麦克风按钮上方。
- 输入框采用 `.ultraThinMaterial` + 浅描边。
- 麦克风按钮采用双层圆结构：外环 glow + 内层玻璃按钮。
- 第一层阶段只实现视觉和输入状态，不强绑定业务发送逻辑。

## 分阶段任务

### Phase 1: 首屏骨架与间距基准
- 调整卡片容器尺寸、圆角、内边距。
- 确定标题区、球体区、底部交互区三段式垂直节奏。
- 建立小屏与大屏的响应式尺寸区间。

交付物：
- 第一层静态布局可显示。
- 标题、球体占位、输入框、麦克风位置正确。

### Phase 2: 球体与 mesh 特效
- 实现 `AIChatOrbView`。
- 实现 `AIChatOrbSceneView` 中的 mesh 背景层。
- 接入球体缓动、色斑流动、外环旋转和高光。

交付物：
- 球体具备液态玻璃质感。
- mesh 可见且缓慢旋转。
- 整体视觉接近 `test.html` 第一层中心区域。

### Phase 3: Prompt Tag 与底部交互区
- 实现 3 个悬浮 prompt tag 的固定锚点布局。
- 完成输入框、发送按钮、麦克风按钮视觉。
- 处理键盘弹起时的底部区避让。

交付物：
- 第一层完整首屏结构可用。
- 输入框与麦克风区域视觉与 HTML 首屏一致。

### Phase 4: 细节打磨与性能优化
- 调整透明度、模糊、阴影、颜色过渡。
- 限制动画数量和更新频率。
- 在真机上检查掉帧、过曝、锯齿和文本遮挡问题。

交付物：
- 首屏视觉收口。
- 动画在常用机型上保持稳定流畅。

## SwiftUI 技术决策

### 推荐方案
- `TimelineView(.animation)`
  - 驱动球体和 mesh 的持续动画。
- `Canvas`
  - 绘制 mesh 和部分球体光效。
- 自定义 `Shape`
  - 生成轻微呼吸形变的球体轮廓。
- `blur` / `overlay` / `mask` / `blendMode`
  - 模拟液态玻璃折射与高光。

### 不建议方案
- 不直接追求把 HTML/CSS 参数逐项翻译成 SwiftUI。
- 不在第一阶段引入过多粒子系统。
- 不把 Layer 2/3 的动画需求和第一层视觉复刻绑在一起。

---

## 风险与退化策略

### 风险 1: SwiftUI 无法 1:1 复刻 CSS inset shadow
解决：
- 接受“视觉等效”而非“像素级等效”。
- 使用 overlay + blur + blend mode 模拟内部折射。

### 风险 2: 球体形变动画成本过高
解决：
- 先做低频轻形变。
- 若性能不足，退化为固定圆形 + 内部流体动画。

### 风险 3: prompt tag 在小屏上遮挡球体或标题
解决：
- 建立紧凑布局版本。
- 在小屏下降低 tag 尺寸并重排锚点。

### 风险 4: 输入框和键盘避让破坏首屏节奏
解决：
- 第一优先级为整体卡片轻微上移。
- 若效果不佳，再退化为仅底部区上移。

## 验收标准

### 视觉结构验收
- 卡片高度应占可用高度约 82% 到 90%。
- 标题最大宽度应明显小于卡片宽度，保持左上聚焦感。
- 球体必须位于卡片视觉中心略偏上位置。
- 输入框、`Hold to Talk`、麦克风按钮必须形成稳定竖向链路。

### 球体效果验收
- 球体尺寸应在卡片宽度的 36% 到 48% 之间。
- 球体至少包含 3 层内部流体色斑。
- 球体必须存在顶部高光和外围 glow。
- 球体动画应包含缓慢呼吸或轻微形变，不可完全静止。

### Mesh 层验收
- 背景 mesh 必须可见，但透明度不能抢过球体主体。
- mesh 必须缓慢旋转，周期建议不短于 20 秒。
- mesh 不得遮挡 prompt tag 主文字。

### Prompt Tag 验收
- 必须有 3 个标签，且默认全部可见。
- 标签锚点应接近 `test.html`：左上、左下、右中。
- 标签边框、毛玻璃和阴影必须成立，不能退化为普通按钮。

### 底部交互验收
- 输入框与麦克风按钮间距应维持在 14 到 24 pt。
- 麦克风按钮必须为双层圆形结构，而非单层实心圆。
- 输入框聚焦时，不得遮挡标题或球体主体。

### 性能验收
- 常驻动画在真机上应保持流畅，无明显掉帧。
- Instruments 中 CPU/GPU 占用不能因首屏特效长期异常偏高。
- 动画层数过高时，应优先退化 mesh 或球体形变，而不是去掉主视觉结构。

---

## 验证方法
- 使用 SwiftUI Preview 对照 `test.html` 首屏截图逐项比对。
- 在至少 2 种尺寸设备上验证：一台小屏，一台大屏。
- 使用真机录屏检查动画是否存在卡顿和闪烁。
- 使用 Instruments 观察首屏静置 30 秒时的性能表现。

---

## 最终完成定义
满足以下条件后，判定“已实现 `test.html` 第一层效果”：
- 第一眼构图与 `test.html` 首屏一致。
- 中心球体具备液态玻璃质感与动态 glow。
- mesh、prompt tag、输入框、麦克风区全部到位。
- 在小屏和大屏下都没有明显遮挡、溢出或错位。
- 动画流畅，且代码结构支持后续再接 Layer 2/3。
