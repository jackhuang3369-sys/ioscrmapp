# 能力：weather-sun-transition-smoothness

## 需求（规范）

1. 系统必须将"第一屏点击太阳进入第二屏"的主转场时长缩短到约 0.35~0.40 秒量级。
2. 系统必须将"第二屏返回第一屏"的主转场保持在约 0.20~0.25 秒量级，并避免观感突兀；返回时 SwiftUI overlay 渐隐时长需与 SceneKit 返回时长匹配。
3. 当需要进行"进入前正面对齐"时：
   - 系统必须将该预对齐时长控制在约 0.10~0.14 秒量级；
   - 正面容忍度从当前 8° 放宽到 15°~20°；
   - **主转场必须在预对齐 `completion` 回调内启动**，不得与 SCNTransaction 并行竞争导致时长叠加。
4. 系统必须让 SwiftUI overlay 显示与 SceneKit 主转场在同一时间线启动：进入时**立即置 `isSunDetailPresented = true`**（结构瞬间完整出现），`detailOverlayOpacity` 在 ~0.22~0.26s 内完成渐显；面板子视图使用各自独立的渐显动画，不出现整体闪现。
5. 系统必须将关键标题/信息（例如 SUN 文字）出场时机提前到主转场前段（reveal delay 从 60% 调整到 15~20% 主转场进度，reveal 时长缩短到 20% 主转场进度）。
6. 触觉反馈总时长（约 0.38s）需与视觉主转场一致，burst 可略提前但不延长整体感知时长。
7. **新增**：系统必须将第二屏点击太阳的射线爆发总时长从 1.0s 缩短到约 0.50s，`tailStartFraction` 从 0.30 调整到 0.20，使射线更快速、更有爆发力。
8. 系统不得引入新的页面结构、手势交互模型或渲染框架迁移（仍使用当前 SceneKit + SwiftUI 方案）。

## 验收标准

- 在小屏与大屏设备上，点击太阳进入第二屏的总体体感明显更快，且不出现分段拖尾（从点击到"可交互"含预对齐时 < 0.58s，不含预对齐时 < 0.52s）。
- 在进入第二屏时，SceneKit 主运动结束时 SwiftUI overlay 已基本到位（无 0.2 秒级别的"UI 继续慢慢显"的脱节）；面板无闪现感。
- 标题出场不再"慢半拍"，与点击/主运动节奏一致（标题在主转场 15~20% 进度时开始出现）。
- 返回第一屏时动画短促但不生硬，overlay 渐隐与 SceneKit 返回同步完成；状态机无卡住（交互恢复及时，`isSunTransitionActive` 正确归零）。
- 快速连点场景（点击→返回→点击）下，`isSunTransitionActive` 正确阻止重入，无状态残留。
- **新增**：第二屏点击太阳时射线爆发更有力度感，总时长从约 1.228s 缩短到约 0.728s（改善 40%），无"慢悠悠"的感觉。
